# Crux PE13 Actions builds and ZIP releases

- This checkout owns the `aosp_crux-userdebug` cloud build, its verification and its signed TWRP ZIP release. Start with the [repository README](README.md) and the [standard-runner acceptance and rerun guide](docs/standard-runner-rom-build-acceptance-2026-11-05.md). The local OrbStack build compiles the same pinned code and packages the same ZIP with `scripts/crux_zip.py` and `installer/`; it never publishes here.
- Use public-repository standard GitHub-hosted `ubuntu-22.04` runners under the GitHub Free plan: no larger or self-hosted runners and no paid usage. Private inputs come only from the two pinned GitHub snapshot repositories through `CRUX_SOURCE_SNAPSHOTS_TOKEN`; build artifacts, logs and releases in this repository are public. The compile admits a preparation run from its own artifacts and those of the freeze and index runs it names; `docs/evidence/` is history, not an input. To rebuild manually, follow the [freeze and prepare procedure](docs/standard-runner-freeze.md). Preserve current-execution admission receipts, original native provenance for content-verified reuse, and the paired kernel, DTBs, overlay, ramdisks and symbols. Do not substitute a foreign receipt for current admission or bypass pipeline-code checks. `force_cold` disables native output reuse, not source integrity checks; ccache stays disabled.
- [nightly.yml](.github/workflows/nightly.yml) pins moved sources as `github-actions[bot]` and starts a full freeze; each full stage dispatches the next, from the freeze to [release.yml](.github/workflows/release.yml), which signs and publishes the assembly's ZIP. Failures open or update the build's issue. A manual run of a stage takes the previous stage's successful run ID (`graph_run`, `pack_run`/`shard_run`, `build_run`, `assembly_run`) and continues the chain from there. Do not manually upload or repackage accepted ROM images or use local outputs as inputs.
- The install key exists as the owner's local copy and as the `CRUX_INSTALL_SIGNING_KEY` secret of the `install-signing` environment, limited to `main`; keep it out of every repository, log, artifact and synced note. Only release.yml's `sign` job reads it: it uses no third-party action and uploads nothing. `keys/crux-b-install-2026-11-07.pub.pem` verifies every signature, and `config/install-twrp.json` pins the RAM-only install TWRP that every release carries.
- Assistants still need the owner's authorization to dispatch, push or change repository settings; the scheduled chain runs on its own. Preflight does not mutate Releases. Releasing stays separate from device installation.
- Before a local build, run `scripts/check_local_source.py` against the VM source tree: the local build is the same code only when it reports no problems.
- For code changes, run the relevant unittest subset from this checkout, for example `python3 -m unittest tests.test_crux_zip tests.test_release_zip tests.test_release_source` for packaging and release, and `make -C installer test` for the installer. Broaden to `python3 -m unittest discover -s tests` for shared pipeline changes and use `actionlint` for workflow changes. Hosted build, release and device acceptance are separate checks.
